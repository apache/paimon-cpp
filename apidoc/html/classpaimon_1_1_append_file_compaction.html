Synchronously compacts files and returns messages for FileStoreCommit::Commit or Abort.

Each call creates a dedicated batch writer and restores the latest snapshot for the bucket. Writes one file in file name order, preserving surviving physical row order within each input. Ignores target-file-size; produces no file when all input rows are deleted. Supports deletion vectors; real-time mode and data evolution are unsupported. Requires bucket-append-ordered=false and write-only=false. With deletion vectors enabled, callers must serialize compactions within each partition/bucket, even for disjoint inputs. Do not start another compaction, update deletion vectors or overwrite this partition/bucket until the messages are committed or discarded. Without deletion vectors, compactions of disjoint input files may run concurrently in the same partition/bucket. Overlapping compaction or overwrite may cause commit conflicts. Failures may leave orphan files for later cleanup.
