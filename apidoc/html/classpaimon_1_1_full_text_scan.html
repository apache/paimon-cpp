Detailed Description

Plans a table-level full-text search into splits, aligned with Java org.apache.paimon.table.source.FullTextScan.

Create one with FullTextSearchBuilder::NewFullTextScan().

virtual Result< std::shared_ptr< Plan > > paimon::FullTextScan::CreatePlan ( )
pure virtual

Plans the search on the snapshot that the options select, as Java TimeTravelUtil#tryTravelOrLatest does: snapshot scan.snapshot-id, the snapshot of tag scan.tag-name, the latest snapshot at or before scan.timestamp or scan.timestamp-millis, or else the latest snapshot.

As in Java, at most one of these options may be set, and it must agree with an explicit scan.mode: from-snapshot needs scan.snapshot-id or scan.tag-name, from-snapshot-full needs scan.snapshot-id, from-timestamp needs scan.timestamp or scan.timestamp-millis, and latest-full and latest take none of them.

Each index shard of the searched column becomes one split. The scan considers only the index files that are in the partitions of the partition filter, that index the column as their indexed field or as one of their extra fields, and whose indexer supports full-text search (GlobalIndexer::SupportsFullTextSearch()). The plan fails if Paimon C++ is built without the backend of a full-text or lucene-fts index it finds. When the row ranges of index shards overlap, each row is ranked by one shard only: an index whose indexed field is the column comes before one that carries it as an extra field, and further ties are broken by index type and fields, then by the start and end of the shard.

Returns
The plan, or an error if more than one time-travel option is set, the option does not agree with scan.mode, the selected snapshot or tag does not exist, or reading the index manifests fails; NotImplemented for an index whose backend is not built.
