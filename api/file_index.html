File Index#

Full-text predicates and root TopK#

PredicateBuilder::FullTextMatch creates a LeafPredicate for a full-text condition without TopK truncation. It holds a shared FullTextMatch request, whose query uses the same JSON DSL as FullTextSearch. Do not modify a request after passing it to a predicate or read context.

Compose full-text and scalar predicates with the existing PredicateBuilder::And and PredicateBuilder::Or factories. Every field referenced by this tree must appear in the read schema; field indices refer to positions in that schema. For example, the following constructs body matches "apple" OR price < 10:

auto request = std::make_shared<paimon::FullTextMatch>(
    "body", R"({"match":{"query":"apple"}})");
PAIMON_ASSIGN_OR_RAISE(
    std::shared_ptr<paimon::Predicate> text,
    paimon::PredicateBuilder::FullTextMatch(0, request));
auto price = paimon::PredicateBuilder::LessThan(
    1, "price", paimon::FieldType::INT, paimon::Literal(10));
PAIMON_ASSIGN_OR_RAISE(
    std::shared_ptr<paimon::Predicate> filter,
    paimon::PredicateBuilder::Or({text, price}));
paimon::ReadContextBuilder builder(table_path);
builder.SetReadFieldNames({"body", "price"}).SetPredicate(filter);

SetVectorSearch and SetFullTextSearch configure a separate root TopK request. They are mutually exclusive and require a positive limit. The intended semantics are to filter by the complete predicate before ranking; the TopK search field does not need to be projected. A full-text match inside a predicate never has a TopK limit.

Score output is requested through an explicit _<field>_INDEX_SCORE projection. For example, request the score of a full-text predicate by projecting _body_INDEX_SCORE:

auto request = std::make_shared<paimon::FullTextMatch>(
    "body", R"({"match":{"query":"apple"}})");
PAIMON_ASSIGN_OR_RAISE(
    std::shared_ptr<paimon::Predicate> text,
    paimon::PredicateBuilder::FullTextMatch(0, request));
paimon::ReadContextBuilder builder(table_path);
builder.SetReadFieldNames({"body", "_body_INDEX_SCORE"}).SetPredicate(text);

Score fields have type float32 and preserve the source field’s exact name, including case. Select them with SetReadFieldNames or SetReadSchema; they have no persistent field IDs for SetReadFieldIds. Reading all table fields does not implicitly add score fields.

Each projected score must have exactly one search condition as its source. The source may be a root TopK request or a full-text predicate. A full-text predicate whose score is projected cannot have an OR ancestor, and its field cannot occur in another search condition, including the root TopK request. An ordinary scalar predicate on the same field is allowed. For example, when projecting the score of match, match AND (p OR q) is valid, while match OR p is rejected. Without that score projection, both OR branches and repeated full-text search fields are allowed. These checks use the effective read projection, after resolving the read schema.

virtual Result<PAIMON_UNIQUE_PTR<Bytes>> SerializedBytes() const#

Serializes the built index into a byte buffer.

Streaming-only writers may override WriteTo() and use the default NotImplemented result from this method.

Note

This method returns the complete serialized form of the index after all batches have been added. It can be called only once and typically assumes no further calls to AddBatch() will occur afterward.

Returns:

A unique pointer to a byte array containing the serialized index data, or an error if serialization fails.

virtual Result<bool> WriteTo(OutputStream *output) const#

Writes one index payload to the caller-owned stream without closing it.

The stream is borrowed for this call and must not be retained by the writer. The supplied stream must report positions relative to the start of this index payload. The default implementation writes SerializedBytes(); streaming writers can override this method to avoid materializing the complete payload. Write failures must be propagated.

Returns:

true if a non-empty index payload was produced, false if there is no index, or an error. Returning false must not write any bytes. The default implementation treats null or zero-length SerializedBytes() results as no index.

class FileIndexReader : public paimon::FunctionVisitor<std::shared_ptr<FileIndexResult>>#

Evaluates filter predicates against a file-level index to determine file eligibility.

FileIndexReader implements the FunctionVisitor interface specialized to produce std::shared_ptr<FileIndexResult> objects. It reads pre-built file-level index data (e.g., bitmap, bsi or bloom filters) from index file and evaluates whether a given data file may contain rows matching a specific predicate.

Note

Callers of Visit* for DECIMAL fields must ensure each literal’s scale matches the scale of the indexed data; otherwise, index filtering results may be incorrect.

class FileIndexFormat#

Defines the on-disk format and versioning for Paimon file-level indexes.

Supports V1 and V2 containers. V2 uses int64 offsets and lengths and supports streaming index payloads directly to the output; avoiding full payload buffering requires a streaming WriteTo() implementation in the index plugin. See file_index_format_v1.h and file_index_format_v2.h for the serialized layouts.

Public Types

using ColumnIndexes = std::map<std::string, std::map<std::string, std::shared_ptr<Bytes>>>#

Serialized file indexes grouped as column name -> index type -> index bytes.

A null bytes pointer represents an empty index for that column and index type. For example, indexes[“col1”][“bsi”] = <bytes>;

V1 buffers payloads; V2 writes them directly to the destination. An empty callback or a false result denotes an empty index (-1, 0). A true result indicates that a non-empty payload was written. Call Finish() after the last index. Payload failures are terminal.
