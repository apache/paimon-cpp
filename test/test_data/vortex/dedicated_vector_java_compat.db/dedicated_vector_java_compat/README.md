# Dedicated VECTOR Java Compatibility Fixture

This table was generated on 2026-10-16 by the Paimon Java batch write API,
then read back and checked by Java before copying the table files here.
The C++ `DataEvolutionTableTest.TestReadJavaDedicatedVectorStore` test reads
these files without rewriting them. Metadata was generated by Java together
with the data files.

Writer provenance:

- Apache Paimon Java `2.2-SNAPSHOT`, source commit
  [`7d6d146bbaf33a349dc83c3caf71334bd551e3d5`](https://github.com/apache/paimon/commit/7d6d146bbaf33a349dc83c3caf71334bd551e3d5).
- Vortex native library from `dev.vortex:vortex-jni:0.73.0`, as selected by
  that Java source revision; Arrow Java `15.0.0`.
- Amazon Corretto JDK `17.0.20.1` (`17.0.20.12.1`), Maven `3.9.16`,
  macOS `15.5`, `aarch64`.
- `GenerateDedicatedVectorFixture.java` is the generator used for this table.
  `pom.xml` supplies its runtime classpath after building the pinned revision.

Schema (all three columns are nullable):

```text
id INT
embedding VECTOR<FLOAT, 3>
tag STRING
```

Options:

```text
file.format = parquet
vector.file.format = vortex
bucket = -1
row-tracking.enabled = true
data-evolution.enabled = true
write-only = true
```

`write-only` prevents background compaction so that the two append commits
remain distinct. Every non-null vector has three non-null FLOAT elements.

| Snapshot | id | embedding | tag |
|---|---|---|---|
| 1 | 1 | [1, 2, 3] | a |
| 1 | 2 | NULL | b |
| 1 | 3 | [-1, 0, 1] | c |
| 2 | 4 | NULL | d |
| 2 | 5 | [7, 8, 9] | e |
| 2 | 6 | [10, 11, 12] | f |

The table has two Parquet main files with `writeCols=[id, tag]` and two
`.vector.vortex` files with `writeCols=[embedding]`. The first main/vector pair
has `firstRowId=0`; the second pair has `firstRowId=3`. Each file has three
rows. The 14 Java-generated table files total 17,178 bytes, excluding this
README and the generator sources.

## Reproduce

Run from the Paimon C++ repository root with JDK 17 and Maven available.
This creates a new temporary warehouse and leaves the checked-in fixture
untouched.

```bash
fixture_dir="$PWD/test/test_data/vortex/dedicated_vector_java_compat.db/dedicated_vector_java_compat"
generation_dir="$(mktemp -d)"
git clone https://github.com/apache/paimon.git "$generation_dir/paimon"
git -C "$generation_dir/paimon" checkout 7d6d146bbaf33a349dc83c3caf71334bd551e3d5

mvn -B -ntp -f "$generation_dir/paimon/pom.xml" \
    -pl paimon-vortex/paimon-vortex-format -am \
    -DskipTests -Dcheckstyle.skip -Dspotless.check.skip \
    -Drat.skip=true -Dlicense.skip=true install

mvn -B -ntp -f "$fixture_dir/pom.xml" \
    org.apache.maven.plugins:maven-dependency-plugin:3.6.1:build-classpath \
    -Dmdep.outputFile="$generation_dir/classpath.txt"

java --add-opens=java.base/java.nio=ALL-UNNAMED \
    --class-path "$(cat "$generation_dir/classpath.txt")" \
    "$fixture_dir/GenerateDedicatedVectorFixture.java" \
    "$generation_dir/warehouse"
```

The Arrow Java memory implementation requires the `--add-opens` argument.
The generator creates the database and table, appends each three-row batch
in a separate commit, and verifies all six rows, NULL vectors, and paired
row-range metadata with Java. A successful run prints `Java readback verified`
and the four file metadata records, and exits with code zero.

The generated table is under
`$generation_dir/warehouse/dedicated_vector_java_compat.db/dedicated_vector_java_compat/`.
UUIDs, timestamps, and commit users change when regenerating; row values and
row-range relationships remain the same.
